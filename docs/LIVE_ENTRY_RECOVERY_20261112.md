# Live 入场：面板误禁用与摄影空间对齐

## 问题与依据

- 用户提供的会话末尾记录了：配套 Live 舞台成为活动场景 → 原生时间轴开始异步载入 → 摄影角色集合变化 → `stage restoration failed during actor replacement` → 拍照保护被永久标记为未就绪，面板停在禁用页。
- `SourceScene::Release()` 在异步取消、卸载尚未结束时返回 false，这是待重试状态，不等于拍照钩子损坏。此前角色刷新却直接调用 `ProtectedCaptureFault()`。
- 摄影背景替换原本只重定向资源键，没有对齐原摄影背景的角色位置与 Live 空间。用户补充现象为“镜头在下面，看不到偶像”。坐标不匹配是基于代码路径的判断，本次没有读取或操作游戏来确认具体机位。

## 修改

### 角色刷新

- 普通角色变化保持舞台注入暂停，保留异步释放账本，由后续帧重试；不修改拍照钩子的就绪标记。
- 先标记候选节点需要重新发现；恢复完成之前，手动/自动重扫都不丢弃旧身份和静音设置。
- 原有拍照闸门保持严格：异步清理未完成时，`SetInjectionEnabled(false)` 仍返回 false；未将 pending 伪装成成功，也未强制重开拍照保护。

### 原生模板空间

- 装配前从摄影所属场景的实时、类型化快照中重新确认选中角色，读取其世界位置。普通与虚拟角色类型都支持；角色尚未就绪时继续等待。
- 从自有源场景读取原生虚拟演员锚点；多个演员时要求唯一的 `VirtualActor_00`。这个名称见用户提供会话的既有源场景检查结果，不是逐首硬编码高度。
- 没有虚拟演员标记时采用源场景世界原点作为兼容基准；这是回退约定，不代表逐首验证过所有舞台。
- 偏移量为“摄影角色原点 − Live 演员原点”。配套环境和自有源场景使用相同平移父节点；不移动摄影演员、摄影相机或原生相机控制器。时间轴仍写入原来的局部坐标，暂停、采样和跳转不累加偏移。
- 舞台候选扫描透明穿过环境的平移父节点，保留原根节点的深度、背景隐藏与灯光可见性规则。
- 停止/拍照/切换模板仍按现有恢复流程撤回平移：先隐藏源场景、停止时间轴，再还原父子关系与原舞台快照，最后卸载自有场景。失败保留账本；不删除外部新增的子对象。

空间对齐发生在原生模板装配时，需要原有摄影凭据、配套舞台和曲库节拍已经就绪；不是独立的、常驻的手动摄影机位功能。

## 复测

完全退出游戏后，由用户替换 DLL，再选择原来的原生模板重新进入摄影。确认控制面板能够进入曲库，模板装配后可以看到舞台上的偶像，并测试暂停、跳转、停止与再次播放。

日志应出现 `actor replacement: restoration pending; stage injection suspended`（仅在确有待清理任务时）以及 `stage origin aligned offset=(...)`。普通角色刷新不应再产生旧的永久禁用错误。若视角仍异常，偏移日志可用于区分零偏移、源锚点不匹配与摄影相机自身偏离的问题。
